# ADR-0061: per-user 状态作用域留存 —— 按访问续期的过期清扫

- **状态**:Accepted
- **日期**:2026-08-19
- **关联**:ADR-0055(per-user 状态作用域)、ADR-0057(persona 蒸馏)、ADR-0050(记忆时效);
  2026-08 LangChain/LangGraph 工程调研

## Context

ADR-0055 给每个人一份自己的作用域:
`DATA_DIR/v2-scopes/<agentGroupId>/<userScopeKey>/{workspace,claude}`。
它装着**平台落盘的最敏感的东西**——本人的记忆(`CLAUDE.local.md`)、逐字对话归档
(`conversations/`)、Claude 自身状态。

**而它从来没有任何东西会清理。** 会话清扫只管 `data/v2-sessions/`;
`delete-cli-agent` 只在整个 agent group 退役时触发。**一年前就不用了的人,
每一份转录仍然躺在磁盘上。** 这是我们自己在能力边界里列过的合规欠账。

同期对 LangChain/LangGraph 的工程调研给出了三条**成文的坑**(他们文档/issue 里明写),
本 ADR 逐条规避:

1. **绝对年龄 TTL 会删掉正在用的记忆**——因为常用的恰恰是最老的;
2. **"打开 TTL 不清理已有数据"**——只管新写入的留存开关,报告的是一个没兑现的合规状态;
3. **清扫间隔单独配置 = 忘了配就永远不扫**——策略写了却静默不执行。

## Decision

> 新增 `scope-retention`:**按访问续期**的 per-user 作用域过期清扫,
> opt-in(`AGENTDESK_SCOPE_TTL_DAYS`,默认 0 = 关),搭在既有 host-sweep tick 上。

对应三条坑的三条设计:

1. **时钟量的是"废弃",不是"年龄"**。`ensureStateScope`(每次挂载该作用域的 spawn 都会跑)
   写 `.last-access` 戳;清扫比对戳的 mtime。**人还在用,记忆就永不过期**;
   没人说话的作用域自然老去。
2. **不追溯盲区,但也绝不"见即删"**。本特性之前的作用域没有戳 → **收养**:
   打一次戳,此后按这个戳老化。**删除只针对本代码写过的戳**。
   戳的时间优先取**证据**——中央库知道每个 owner 最后一次用某 agent 是什么时候
   (`sessions.last_active`,含 archived 行),所以会话还在的作用域按**真实最后使用时间**收养,
   运营者的策略立即生效;只有连会话都没了才回退到 now(代价:那个作用域多活一个窗口,
   这是"错也要错在安全一侧")。
3. **没有第二个旋钮**。清扫寄生在既有的 60s host-sweep tick 上;
   **设了 TTL 就是全部动作**。启动后首次 tick 会打一行"当前生效策略"的日志
   (开/关、天数),让"静默不执行"无处藏身。

**安全规则**:**任何活跃会话仍解析到的作用域,无论多老一律不删**——
活跃会话集是权威,时间戳不是。(这是"先撤发现面再删载荷"在我们这里的正确形态:
sessions 表就是作用域的发现面,它还指着的东西不能动。)

**审计**:每次过期落一条 `enterprise_audit` 的 `scope_retention_expired`
(agent group、scopeKey、保留天数、最后访问时间)。删掉一个人的记忆与转录是治理事件,
必须留痕。

**孤儿作用域**(agent group 被非常规手段删掉)无需特判:没有会话引用它们,
它们沿同一条路径老化过期。

## 不做什么(Non-goals)

- **这是过期,不是擦除**。"立刻删掉这个人的全部数据"(GDPR 删除权)是**另一个需求**,
  且它牵涉两件本 ADR 无权单方面决定的事:(a)**审计行**——平台被要求保留,
  与"删干净"直接冲突;(b)**后端网关里的记忆**——平台并不拥有它,只能through 契约去**请求**删除。
  擦除需要自己的 ADR 来裁决这两条,不在此预支。
- **不给算力层加第二套策略**:`data/v2-sessions/` 已由 ADR 之前的会话归档/硬删机制管理
  (`AGENTDESK_SESSION_TTL_DAYS` / `AGENTDESK_ARCHIVE_HARD_DELETE_DAYS`),不重复造。
- **不删 group 作用域**(ownerless 的遗留布局):它是 agent group 生命周期的一部分,
  由 `delete-cli-agent` 管理,不按人过期。

## Consequences

- 命名的合规欠账关闭了一半:**过期有了**,可配置、可审计、覆盖存量数据。
- 默认仍是关的——没有运营者会因为升级而丢数据。
- 诚实边界:开着的时候,一个**长期休假**的员工的记忆会过期;
  这正是"按访问续期"想要的语义,但运营者得知道天数该按"最长合理离岗期"来设,而不是按"活跃度"。
- 磁盘增长从"单调递增"变成"与活跃人数成正比"。

## 验证

- `scope-retention.test.ts`(8 例):默认关 / 过期删 / **访问续期救回老作用域** /
  **无戳的存量数据也被覆盖** / **活跃会话作用域永不删** / 落审计行 /
  跨 agent group + 容忍非目录杂项 / 根目录不存在时 no-op。
- 全套本地 CI + 真实 CI 双 job。

## 修正(2026-08-22,合并前红队:4 视角 23 agent,12 条确认,0 条未核验)

**blocker(三个视角独立命中,已修)——目录 mtime 回退量的是"创建时间"而非"最后使用"。**
POSIX 目录的 mtime 只在**它自己的直接条目**增删时前进;作用域根的直接子项只有
`workspace/` 与 `claude/`,在初始化时创建一次,此后所有写入都落在更深层。
于是那个回退对**每一个存量作用域**永远返回创建时间——**正是本 ADR 声称要避免的绝对年龄时钟**,
而且顺序最坏:**资历最老、用得最久的人先被删**。活跃会话那道保险救不了他们,
因为会话在 `AGENTDESK_SESSION_TTL_DAYS` 之后就被归档、退出 `getActiveSessions()`。

**更该记的是:我的测试自己伪造了文件系统不提供的属性**(`utimesSync` 回拨作用域根目录的 mtime),
把错误的心智模型钉成了"通过"。教训:**测试夹具不能替被测系统提供它在真实环境里得不到的输入。**

修正:**收养(adoption)**——没有戳的作用域**一律不删**,先打戳(优先按 `sessions.last_active` 证据,
否则 now),此后按戳老化。整类错误消失:**代码再也不问文件系统一个它答不上来的问题**。

**其余确认项(全部已修):**

- **审计在删除之后写**(major):崩溃在两者之间 = 数据没了却无记录;且审计失败会被日志误报成
  "删除失败"。修正:**审计先写,写失败则中止删除**——不留记录就不做不可逆销毁。
  `rmSync` 非原子,部分失败时审计行已在,运维看得到发生过什么。
- **打戳失败静默**(major):`log.debug` 低于默认 `info` 级别,生产环境不可见;
  而戳一旦停止落地,该用户的留存时钟就冻结了。修正:升级为 **`log.warn`**,并改掉文档里
  "mtime 回退会兜底"这句**假话**(回退只在戳**缺失**时触发,不在戳**过期**时触发)。
- **无指标、无预演**(minor):新增 `scope_retention_total{outcome}`
  (adopted / skipped_live / expired / delete_failed)与 **`AGENTDESK_SCOPE_TTL_DRY_RUN`**
  ——在真实部署上选 TTL 的安全方式:打开预演、看日志、再关掉。预演**不产生任何写入**(含收养戳)。
- **删掉的数据不在备份里**(minor):`scripts/backup.sh` 只备份 SQLite 文件,作用域树不在其中。
  RUNBOOK 补明确警告:**开 TTL 前先备份 `v2-scopes/`**,否则 TTL 设错无从恢复。
- **`.env.example` 缺项**(minor):文档声明它是权威清单,已补两个变量。

测试同步重写:夹具**不再回拨作用域根 mtime**,年龄只通过戳或会话证据表达;
三条 adoption 回归测试在旧实现下**全红**(已验证)。

## 复核修正(2026-08-22,独立核查 agent 对照 12 条逐项验收)

blocker 判定**已真正关闭**(全模块不存在任何从目录 mtime 推导年龄的路径),但核查又抓出
4 条合并前必修 + 若干项,一并处理:

- **文档还在教被删掉的设计**(最该修的两条):RUNBOOK 里"存量数据按目录 mtime 判定"那句
  与新的收养说明只隔三行、互相矛盾;**ADR 索引行逐字保留着 blocker 设计**——而 CLAUDE.md 规定
  该索引是下一个 agent 重建上下文的 ≤3 跳路径,等于在教它那个危险做法。两处均已改写。
- **预演会污染指标**:`adopted` 计数在 `!preview` 守卫**之外**,预演期间同一批作用域每 60 秒
  重复自增,与"预演什么都不写"的承诺直接矛盾。已移入守卫内。
- **卡住的删除会刷审计**:"审计先行"使 rmSync 永久失败(不可变标志/EACCES/挂载卡死)
  变成**每作用域每 tick 一行**治理记录,而审计清理默认关闭 → 无界增长。
  新增 `auditedPendingDelete` 去重:每个卡住的作用域每进程**只审计一次**,删除重试照旧。
- **收养失败仍报成功**:`touchScopeAccess` 返回 void,戳写不进去时也照打"已收养"日志、照加计数
  (且因无戳而每 tick 重复)。改为返回布尔,按实际落地记账,失败计 `adopt_failed`。
- **审计失败无指标**:审计表坏掉时策略静默停摆而所有计数为零——正是规则 3 要防的形态。
  新增 `audit_failed` 计数。
- **未言明的依赖**:`AGENTDESK_SESSION_TTL_DAYS` 不开时会话永远停在 `active`,
  于是**任何有会话的作用域都被当作活跃跳过、永不过期**——单开 scope TTL 会得到一个
  没兑现的合规状态。已在策略日志里加 warn,并写进运维文档。
- **每 tick 一次全表 + 每行一次 sha1**:`userScopeKey` 现按 owner 记忆化;
  `last_active` 为空串时正确回退 `created_at`(原写法会被空串吞掉)。
  诚实残留:仍是 `SELECT *` 全表物化;真长到十万级会话时应换成 SQL 聚合,届时再改。
- **部分删除的行为**已写进模块文档(marker 在被删的树内,两种走向都可恢复,不多删)。
- "never deleted on sight" 的措辞在三处加上**证据限定**——有证据且证据够老的收养
  **本来就应该**当场过期,那是特性不是意外。

新增回归:卡住的删除跑三个 tick 只产生一行审计,障碍解除后仍能正常删除。
